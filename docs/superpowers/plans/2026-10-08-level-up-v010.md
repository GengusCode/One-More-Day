# ONE MORE DAY v0.10 — LEVEL UP Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add short, recoverable South African-inspired education routes and five qualification-aware career ladders without breaking the stable v0.9 life simulation.

**Architecture:** Advance the validated save to schema 10, add data-driven education and career catalogues, and keep all rules in focused system modules. The existing day and timeline engines remain the only owners of time and settlement; the phone renders view models and `js/app.js` coordinates semantic actions and persistence.

**Tech Stack:** Static HTML, CSS, browser-native ES modules, localStorage, Node.js `.mjs` assertion tests, GitHub Pages.

**Spec:** `docs/superpowers/specs/2026-10-08-level-up-v010-design.md`

## Global Constraints

- Preserve every stable v0.9 system: school finale, generated NPCs, phone, week/month skips, aging/endings, nuanced warnings, businesses, travel, money feedback, and chase.
- Show one important decision at a time; education management lives in the phone.
- Include exactly ten initial qualification programmes and five career families with five levels each.
- Only one qualification may be active at a time.
- Weak school results must be recoverable through bridging, knowledge, or relevant experience.
- Never label a choice as the guaranteed good or bad answer.
- Use fictional institution and funding names; do not present game rules as official advice.
- Use `one-more-day-v10`; preserve `one-more-day-v09` until a validated schema-10 write succeeds.
- Every routine financial effect and every checkpoint must be idempotent across reloads and fast-forwarding.
- Remain usable at 320 px, 200% zoom, by keyboard, and with `prefers-reduced-motion`.
- Add no build step, package dependency, framework, backend, campus map, province migration, housing, romance, or unrelated business system.
- The workspace may not contain local Git metadata. Each task still ends in one verified commit; use the connected GitHub contents API with the listed commit message when `git commit` is unavailable.

## Review Focus

- **Malformed or partial v0.9 save:** migration must preserve recognised life/career data and create safe schema-10 defaults — pinned in Task 1.
- **Unknown programme, role, or employer ID:** the game must fall back safely and remain playable — pinned in Tasks 2 and 5.
- **Repeated checkpoint or routine-day resolution:** no duplicated qualification, stipend, fee, loan payment, salary, or result — pinned in Tasks 3 and 4.
- **Insufficient cash on a loan due day:** record arrears and a consequence without duplicate deductions or a soft lock — pinned in Task 3.
- **Conflicting work/study state:** a second course or incompatible paid learnership must fail without mutating the save — pinned in Tasks 2 and 3.
